# Porting little-lang (L) to Tcl 9.1

Notes for whoever works on this next: where the L patch came from, how to
work on it, its status, and the design decisions and pitfalls of the port.

## Origin

The L compiler was originally a fork of Tcl 8.6
(github.com/bitkeeper-scm/little-lang, submodules `tcl`, `tk`, `pcre`).
Upstream tcltk/tcl has a branch `little`: commit `c36102340438` imports the L
fork on top of `990b376ae11f`, so `git diff --ignore-cr-at-eol 990b376ae11f
c36102340438` is the original L patch against 8.6.  The Tk fork only had
build tweaks, so stock Tk 9.1 is used.

## Working on the patch

The simplest way is a git checkout of Tcl at the release tag with the port
applied, then regenerate this repository's files from it:

```sh
git clone https://github.com/tcltk/tcl && cd tcl
git checkout -b little-9.1 core-9-1-0
cp -R ../little-lang-tcl9/overlay/tcl/. .
patch -p1 < ../little-lang-tcl9/patches/tcl-9.1.0-little.patch
# ... hack, build out of tree, test ...
git diff --binary > ../little-lang-tcl9/patches/tcl-9.1.0-little.patch
git status --short | awk '$1=="??"{print $2}'  # new files -> overlay/tcl/
```

Pitfalls:

* 9.1 embeds `library/` in libtcl (zipfs) and does **not** rebuild the zip
  when `library/*.tcl` changes: `rm libtcl9.1.0.zip && make`.
* After editing `Lgrammar.y` / `Lscanner.l` run `make L-gen` in the build
  directory (bison >= 3.8, flex 2.6) and commit the regenerated
  `*-pregen.c` / `Lgrammar.h`, or use `make regen` in this repository.
* `unix/configure` is generated (autoconf 2.73 was used) and is part of the
  patch, so users don't need autoconf.
* `library/Lver.tcl` (the `Lver` proc, needed by test `require-2`) is
  generated by the top-level Makefile.

## Status

* L test suite: 742 passed, 32 skipped (the l-leak tests need a
  `TCL_MEM_DEBUG` build, constraint `memory`), 0 failed.  Clean under
  AddressSanitizer (`CFLAGS=-fsanitize=address -DPURIFY`).
* Tcl core suite with `TCL_REGEXP_CLASSIC=1`: 519942 passed, 1 failed,
  `cmdAH-25.3` (`file owned /`), which also fails with stock 9.1 when run in
  a user namespace where `/` appears owned by the user.
* Tcl core suite with PCRE as default engine: ~300 failures, all in tests
  (or library code: http, idna, ...) that use Tcl (ARE) regexp syntax.  This
  is inherent to making PCRE the default, as it was in the 8.6 fork.
* Built and tested on Linux only.  `win/` (Makefile.in, configure) is not
  ported (needs PCRE, the L objects, etc. as in `unix/`); macOS untested.

Possible further work:

* `TCL_MEM_DEBUG` build (`--enable-symbols=mem`) to run the 32 l-leak tests
  and exercise the non-bitfield `Tcl_Obj.undef`.
* `TCL_COMPILE_DEBUG` build to enable L ASSERTs / TEBC stack checks.
* Update `doc/L` for PCRE2 differences.

## Design decisions / changes vs the 8.6 fork
- **PCRE1 -> PCRE2** (system `libpcre2-8` via pkg-config; `--enable-pcre=yes|no|default`, `--with-pcre=DIR`).
  UTF mode only if pattern has non-ASCII (as fork) + `PCRE2_MATCH_INVALID_UTF`. JIT used if available.
  Tcl's NUL (`C0 80`) converted to real NUL for pattern and subject (`PcreNulCopy`).
  PCRE match offsets normalized to offset-relative char offsets (like classic engine) so GetInfo/Range need no special cases.
  Error text changed (e.g. "quantifier does not follow a repeatable item"); test split-5 now glob-matches.
- `regexp`/`regsub`: `-type classic|pcre`, `regsub -submatches varList`, PCRE subspec escapes (\n \t ...).
  Default engine = interp flag `INTERP_PCRE` (set at interp creation if USE_DEFAULT_PCRE unless env TCL_REGEXP_CLASSIC;
  `interp regexp path ?type?` changes it and bumps compileEpoch). Compile-time ARE->glob optimizations
  (regexp, regsub, switch -regexp) skipped in PCRE interps.
- **Tcl_Obj.undef**: `size_t undef:1; Tcl_Size refCount:63` (separate fields under TCL_MEM_DEBUG).
  Cleared in TclAllocObjStorageEx variants, TclDbInitNewObj; copied in SetDuplicateObj.
  PITFALL: stack-allocated Tcl_Objs (tclGet.c x3, tclIO.c, tclProc.c) must set `obj.undef = 0` — this caused
  `Tcl_GetBoolean("1")` to return false (fconfigure -blocking 1 broke).
- Undef semantics in TEBC: STR_* compare, EQ/NEQ etc., STR_LEN, LIST_LENGTH, STR_MATCH, REGEXP, and 9.1's new
  **INST_IS_EMPTY** (optimizer turns `$x == ""` into it) treat undef as never equal to defined values.
- L opcodes appended to 9.1 opcode enum (tclCompile.h) + table (tclCompile.c); fixed fork's wrong `lsplit` size (2->5).
  Added **INST_L_FOREACH_START/STEP** = port of 8.5-style foreach_start4/step4 (temps in locals, nothing on stack,
  missing values = undef); 9.1 removed those and new-style foreach keeps items on stack which breaks L's
  return/goto-as-jump codegen. STEP pushes a boolean (followed by jumpFalse) instead of the old peephole.
- L codegen now emits only 4-byte opcodes (jumps, load/store/invoke, INCR_SCALAR_IMM); DICT_DONE -> UNSET_SCALAR (OP14).
- Deep-dive (INST_L_INDEX/L_DEEP_WRITE): lists use 9.1 ListStore; `TclDuplicateListRep` rewritten (unshares store,
  removes spans, converts abstract lists). Dict hack (struct with Tcl_HashTable first) still valid in 9.1.
  PITFALL fixed: fork stored the string-index char obj pointer in that obj's own internalRep.ptr2; Tcl 9
  `Tcl_StoreInternalRep` clobbers it -> now kept in `L_DeepPtr.strElemObj`.
  Removed fork's buggy DEEP_WRITE peephole (checked pc+6, leaked refcount).
- INST_EXPAND_ROT: fork read marker depth from ptr1 (link ptr!); now ptr2. PITFALL: use signed Tcl_Size with OBJ_AT_DEPTH.
- `Tcl_GetRange(obj, 0, -1)` means "to end" in Tcl 9 (8.6: empty) — fixed in string deep write.
- Procs: `TclInitByteCodeObj(obj, &tclByteCodeType, env)`, `Proc` memset (new flags field),
  `Tcl_NRCreateCommand2(... TclObjInterpProc2, TclNRInterpProc ...)`, CompiledLocal alloc via offsetof.
  ForeachVarList/ForeachInfo sizes via offsetof (indexes are 8-byte now — ASan caught overflow).
  ECL entries: set `line[0]` and `next=NULL`.
- L commands are `Tcl_ObjCmdProc2` (Tcl_Size objc). ck* allocators -> Tcl_Alloc etc.
- **Byte-wise appends**: Tcl 9 `Tcl_AppendToObj` converts each chunk separately when it starts with a UTF-8
  continuation byte -> scanner string buffer, `L->script`, shsplit now use `Tcl_DString`. `L->script` is
  collected in `L->script_buf` during parse then turned into an obj (kept alive: bytecode points into it).
- Scanner: `0o` octal passed to Tcl directly (Tcl 9 has no leading-0 octal); `\u` hex parsed with strtol
  (TclParseHex is static in 9.1). Grammar: `%define parse.error verbose` (bison 3.8 ignores YYERROR_VERBOSE);
  literal "-nonewline" strdup'd (was freed by ast_free).
- `#lang` pragma parsing (tclParse.c) bounded with memchr (fork used strchr/strstr on non-NUL-terminated input).
- TclEvalEx/TclCompileInvocation/CompileExpanded inject `--line=N` for `L`/`Lhtml` (objv arrays sized +1).
- tclMain: only leading args that are real L options (`L_isCmdLineOption`) are skipped before the script
  (fork skipped every `-x` arg, breaking stock tclsh semantics). `#lang l`/`#lang tcl` interactive switching kept.
- `-epipe exit|error` channel option: queryable but not listed in full `fconfigure` output; puts exits only on
  errno==EPIPE (fork exited on ANY stdout error). Default set by `TclSetStdoutExitOnEpipe()` from Tcl_MainEx,
  applied lazily when stdout is created (creating stdout early broke encoding-24.3).
- `Tcl_WriteObjN` (L write()): binary channels in Tcl 9 use iso8859-1 encoding (not NULL) -> count chars there;
  otherwise round down to char boundary.
- init.tcl sources libl.tcl only in non-safe interps; L globals `%%L_fnsCalled`/`L_fnsDeclared` created lazily on first `L`
  use (safe-6.1). getopt/getoptReset are CMD_IS_SAFE (keep safe-interp hidden list unchanged).
- Disassembler: command source shown exactly (`PrintSourceRangeToObj`, no "..." unless truncated; counts source chars)
  — L src-mapping tests depend on it. Precompiled bytecode disassemblable.
- Error line numbers honor `#line N` (TclLogCommandInfo).
- Test updates: interp/regexp/regexpComp option lists; new tests interp-41.x, regexp-40.x;
  l-core: scan-3.x accept Tcl 9 "cannot use non-numeric string ... as left operand", unicode-4 uses
  `String_length(Encoding_convertto(...))` (string bytelength gone), split-5 glob.
- Scanner: a run-away (unterminated) regexp returned `T_RE` without setting
  the token's string, so the parser reused the previous token's (already
  freed) string -> double free at interp teardown (pre-existing in the fork,
  hidden by Tcl 8.6's zippy allocator; found with ASan, test scan-1.4.4).
- Tcl 9 no longer expands `~` in file names (TIP 602); L's file functions
  don't add it back.  `examples/photos.l` now uses `getenv("HOME")`.
